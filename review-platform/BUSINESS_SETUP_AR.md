# دليل إعداد الأعمال والفروع

## 1) قواعد الامتثال قبل أي شيء

- **لا تنشر صفحة رسمية لنشاط تجاري دون إذن كتابي منه.** قبل الحصول على الإذن تبقى الصفحة «تجريبية» وتظهر عليها عبارة **«نموذج توضيحي غير رسمي»** (تُضاف تلقائياً ولا يجوز إزالتها لتحسين الشكل).
- لا تستخدم شعار النشاط أو هويته البصرية إلا بإذن. الشعار يظهر **فقط** عندما تكون حالة النشاط `approved`.
- لا تدّعِ أي علاقة أو شراكة مع Google.
- لا تقدّم حوافز مقابل التقييم، ولا توجّه العملاء الراضين فقط، ولا تخفِ رابط التقييم عن أي عميل، ولا تُنشئ تقييمات وهمية.
- سحب الإذن: نفّذ `npm run admin -- withdraw biz-001` ثم انشر؛ تتحول جميع صفحات النشاط فوراً إلى «الصفحة غير متاحة».

## 2) الحصول على رابط التقييم الصحيح

الأفضل **Place ID** (يبدأ عادةً بـ `ChIJ`):
1. افتح [Place ID Finder](https://developers.google.com/maps/documentation/places/web-service/place-id) (مجاني، بدون مفتاح) وابحث عن النشاط والفرع.
2. انسخ المعرّف. الرابط الذي يبنيه النظام:
   `https://search.google.com/local/writereview?placeid=<PLACE_ID>&hl=ar`
3. أو الصق رابط مشاركة التقييم المباشر من لوحة Google Business Profile بالشكل `https://g.page/r/<ID>/review`.
> ملاحظة: `hl=ar` يطلب العربية لكن **لا يمكن إجبار** نموذج Google على الظهور بالعربية؛ يعتمد على لغة حساب العميل ومتصفحه.

## 3) التحقق (إلزامي قبل التفعيل الرسمي)

1. افتح الرابط على هاتفك وأنت مسجّل الدخول إلى Google.
2. تأكد أن اسم النشاط **والفرع** المعروضين في نموذج التقييم صحيحان (لا تُرسل أي تقييم فعلي).
3. عندها فقط: `npm run admin -- verify branch-001`.
> رابط التجربة الحالي لـ «جباتي راشد» (`ChIJ_aTomeKZzz8RLgO2Hy19XaM`) **لم يُتحقق منه بعد** ومحفوظ بالحالة `destinationVerified: false`.

## 4) الأوامر اليومية

```bash
cd review-platform
npm run admin -- list                                             # عرض كل البطاقات/الفروع والحالة (تجريبي/رسمي)
npm run admin -- add-business "مقهى الندى" cafe "#7A3E1D"          # نشاط جديد (تجريبي)
npm run admin -- add-branch biz-002 "السالمية" ChIJxxxxxxxxxxxxxxxxxxxxxxx   # فرع جديد ← يُنشئ معرّفاً عشوائياً ثابتاً مثل srgbyq37h4qf (لا يتغير أبداً)
npm run admin -- verify branch-002                                # بعد التحقق اليدوي
npm run admin -- activate branch-002                              # تفعيل
npm run admin -- set-destination branch-002 <placeId أو رابط>      # تعديل الوجهة بدون المساس ببطاقة NFC (يلغي «تم التحقق»)
npm run admin -- disable branch-002                               # إيقاف الصفحة
npm run admin -- set-theme biz-002 "#7A3E1D"                      # اللون (يُرفض إن كان تباينه ضعيفاً)
npm run admin -- approve biz-002                                  # فقط بعد إذن كتابي: يزيل عبارة «نموذج توضيحي»
npm run dev                                                       # معاينة محلية: http://localhost:4321/r/branch-002
```
بعد التعديل: `git add -A && git commit && git push` ثم تنشر الاستضافة تلقائياً (دقيقة تقريباً).

## 5) الشعار (اختياري)

ضع الملف في `public/logos/<اسم>.svg|png|webp` (حروف صغيرة وأرقام وشرطات فقط) وأضف `"logo": "/logos/<اسم>.svg"` في `data/businesses.json` للنشاط. يظهر فقط للأنشطة `approved`؛ وإن فُقد الملف تُعرض أيقونة الفئة تلقائياً.

## 6) قواعد المعرّفات

- المعرّف (12 رمزاً عشوائياً، أو `branch-001` للتجربة فقط) **ثابت للأبد**: لا يُعاد استخدامه لنشاط آخر ولا يُحذف. للإيقاف استخدم `disable`. يفرض ذلك الملف `data/assignments.lock.json` ويفشل البناء عند المخالفة.
- يمكنك تعديل `data/businesses.json` يدوياً، ثم شغّل `npm run validate` للتحقق.

## 7) حالات الصفحة

| الحالة | ما يراه العميل |
|---|---|
| `active` + نشاط `demo` | الصفحة كاملة + «نموذج توضيحي غير رسمي» |
| `active` + نشاط `approved` (والوجهة موثّقة) | الصفحة كاملة بدون عبارة التجربة، مع الشعار إن وُجد |
| `disabled` / `draft` / نشاط `withdrawn` | «هذه الصفحة غير متاحة حالياً» — بلا زر ولا اسم نشاط |
| معرّف غير موجود | «الصفحة غير موجودة» (404) |
